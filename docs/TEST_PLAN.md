# 测试与验收计划

## 当前骨架检查

`skeleton_tests`只验证已提供的输入基础：字母/越界/溢出/尾随字符能重试、上下边界可接受、EOF返回-1、课程菜单正确转换、错误范围被拒绝。它不检查未实现的游戏逻辑。

当前菜单演示应能退出、返回、取消；选择占位行动后Player仍是初始值，日期保持第1天早上，并显示待实现提示。这个结果只证明骨架运行，不代表游戏功能。

## 模块完成后逐项验证

| 模块 | 正常场景 | 重点边界/反例 |
|---|---|---|
| 状态 | 合法值保持；夜间恢复 | 负数/超过100；金钱负数；反复normalize |
| 复习/休息 | 指定课程变化；恢复 | 非法课程状态不变；满值仍有效；低精力可崩溃 |
| 娱乐/兼职 | 效果逐字段对照 | 课程不变；压力截到0；精力归零 |
| 商店 | 三种商品；恰好够钱 | 少1元；非法商品/资料课程；失败整个状态不变 |
| 事件 | ID1～4效果 | 无事件/非法ID；最低课程并列；每天最多1次 |
| 结局 | 四种分支 | 59/60、79/80、0精力、100压力、崩溃优先、未完成 |
| UI | 菜单与状态可读 | 取消、EOF、字母；显示截断后的实际差值 |
| 主流程 | 15次成功行动 | 失败不耗时；崩溃后停止；第5天不恢复 |

添加测试时验证预期业务行为，不要把当前占位返回false/无效果写成永久正确答案。测试不能只抄实现中的条件。

## 完整游戏路线（尚待实现后运行）

先通过测试入口明确指定每晚事件ID为0，隔离随机影响；不要假装仅设定随机seed就一定没有事件。测试结束恢复正常抽取。

### 过关路线

学霸路线前4天，第5天三次休息。无事件时预期：三课各65、精力100、压力0、金钱30，Pass。

### 挂科路线

连续休息15次。无事件时预期：三课各20、精力100、压力0、金钱30，Retake。

### 崩溃路线

持续复习高数。无事件时预期第6次有效行动后精力0，立即Burnout，不触发当晚事件或恢复，也不能继续选择行动。

## 随机与端到端

效果测试直接传ID，抽取概率另行统计。正式运行至少完整玩一局正常随机事件游戏，记录事件与行动实际数值；再用固定事件序列重现问题。若声明四个结局都能从初始状态到达，应分别记录实际运行路线，不能只直接构造最终Player测试判定函数。

前期独立JavaScript规则模型曾对上述每条路线各枚举3125种日事件组合，结局均符合预期；持续复习在第6～8次行动崩溃。这是设计模型证据，不是本仓库C++实现验证。当前C++业务函数仍未实现。

## 交付前反证检查

- 能证明：明确列出所用编译器、实际运行的程序/输入、实际输出和通过的测试。
- 不能证明：占位模块、未走过的路线、未运行的平台不能声称已完成或已验证。
- 从远程仓库新建干净克隆后再编译，确认没有依赖本机未提交文件。
- 在 TEST_RESULTS.md 中填实际结果，未运行的保留“未执行”。
